OmniTavern · 女仆 · 设计评估 v2

女仆执行卡：让“正在做什么”一眼可见

一次女仆任务改为一个运行对象：头部说清目标与进度，只放大当前步、失败步和需要你处理的事。女仆的思考和执行过程默认折叠，但女仆对你说的话（汇报、提问）始终显示。电脑和手机分别设计；语音任务只显示三拍摘要：接收、执行、汇报。

v2 · 已按你的意见确定

四项决定

  • 语音

    只显示摘要

    下达任务 → 女仆执行 → 用语音汇报结果。托盘里每个任务只有一行指令、一条三拍进度和一句结果，要看步骤时再点“查看详情”。

  • 状态

    去掉汉字，改用三重编码

    每种状态有不同的图标形状和颜色，头部另有文字状态。色弱或灰度下也能靠形状分辨。

  • 折叠

    过程折叠，汇报必显示

    思考和工具步骤默认折叠；女仆的最终汇报、中途提问和需要你处理的提示，总是以带“侍”标记的气泡显示在卡片外。

  • 确认

    语音说“允许”即允许一次

    简体、繁体、英文的说法同步支持。语音永远不能触发“始终允许”，这一项只在按钮上提供。

现状

现在的卡片为什么看不出重点

  1. 1

    每一步都是同等分量的一张卡。 完成、失败、等你确认的步骤在外框、字重和高度上都一样；结果流最高 188px，约放 3 张。

  2. 2

    状态靠汉字表达。 计/行/成/败 要读才懂；真正表示状态的圆点只有 6px。

  3. 3

    等宽标签 TOOL · 01 占去最显眼的位置。 它是序号，不是“做了什么、对谁做”。

  4. 4

    数据有，界面上没显示。 参数、结果、耗时、读回验证、todo、用量都已在 AgentRun 里。

  5. 5

    确认会跳出模态框。 流里只显示“等待授权”，按钮在屏幕中央的弹窗里；通话中也一样，没有口头确认的通道。

  6. 6

    语音任务只剩一行字。 小球旁只显示“正在读取设置”这样一行文字，看不出任务到了哪一步。

提案 · 可交互

运行卡原型：电脑与手机

切换状态、设备，或点“播放全过程”。在手机视图里，点抽屉顶部的横条可以在预览、半屏、全屏之间切换。示例任务：为三个角色建私聊并绑定世界书。

状态：形状 + 颜色 + 文字

  • 排队空心圆，灰字
  • 执行中旋转弧，标题加粗
  • 等你确认琥珀时钟 + 卡内确认块
  • 完成灰色细勾，不抢视线
  • 失败红叉，原因紧跟在下方
  • 跳过短横

什么折叠，什么始终显示

折叠：思考（“思路”）、已完成的步骤、参数与结果。始终显示：带“侍”标记的女仆汇报气泡，包括最终结果、中途提问（例如失败后问“要先创建角色卡吗？”）和需要你处理的提示。

颜色只用在一处

单步完成用灰勾；绿色只留给整次任务成功时的头部对勾。

适配

电脑和手机各自怎么看最方便

不按单一宽度阈值切换：宽度 ≤ 760px 且主要靠触控（pointer: coarse）时用手机方案；宽屏触控设备（平板）沿用电脑布局，但放大点击区。

方面电脑：锚定小球的浮动卡手机：底部抽屉
位置跟随小球，位于输入胶囊的上方或下方，沿用现有的翻转逻辑；可以移到侧边停靠（即执行流面板）。从底部升起，拇指可及。输入胶囊固定在抽屉底部，跟随键盘上移（visualViewport + 安全区）。
高度上限 min(60vh, 480px)，超出部分在卡内滚动。完成后自动收成头部 + 汇报。三档：预览约 150px（头部 + 当前一行）、半屏、全屏。执行中默认预览，等待确认或失败时升到半屏，看详情时拉到全屏。
展开悬停时出现箭头，点击后在原位展开参数和结果；键盘 ↑↓ 移动，Enter 展开。箭头常显；每行点击区至少 44px；展开详情时抽屉自动拉到全屏，不在半屏里挤。
确认在卡内原位显示；Enter 允许一次，Esc 取消，危险操作的默认焦点放在取消上。确认块固定在抽屉底部、输入胶囊的上方，按钮加大；不用滚动就能点到。
自动滚动离底部 28px 以内才跟随；用户往上翻时不打断。预览档只显示当前一行，不滚动；半屏以上沿用电脑的跟随规则。
关闭点外部或按 Esc 收起；任务继续在后台执行，小球外圈显示进度。下滑到底或点遮罩收起；同样不会中止任务。
规则

视觉重点的三级阶梯

同一时刻只有一个第一层。落地时每个元素都要能归进其中一层，归不进去的就删掉。

第一层 · 现在要看

当前步 / 待确认 / 失败 / 女仆汇报

黑字加粗、带色图标，操作按钮紧贴在旁边。汇报气泡同属这一层，但只在任务结束或需要你回应时出现。

第二层 · 我在哪

目标、进度、耗时、来源

头部一行：进度环、目标、执行中 · 2/4 · 12.4s。停止按钮常驻右侧。

第三层 · 需要时再看

已完成步骤、参数、结果、思路

灰字单行，默认折叠；超过 2 步的已完成部分收成“已完成 N 步”。

Realtime · 语音

语音任务：只显示接收、执行、汇报三拍

用户用语音下达任务，正是因为不想盯着屏幕，所以语音侧只回答三个问题：她听懂了吗？在做了吗？做完了吗？结果会用语音播报，屏幕上只留一句话，想看步骤时再点开。

小球外圈与胶囊

外圈只分状态，不显示步骤进度：接收和执行时蓝色慢转，等待确认时琥珀色呼吸，汇报完成时绿色停留 1.2 秒，失败时红色保留到你查看为止。胶囊只放一句话，内容就是她此刻会对你说的那句。

托盘里每个任务三行

第一行是你说的话（指令摘要），第二行是接收、执行、汇报三拍进度，第三行是一句结果或当前在做的事，外加“查看详情”。点“查看详情”才会打开完整运行卡，所以步骤列表不会出现在语音托盘里。

口头确认

需要确认时，托盘自动展开，女仆口头询问。说“允许 / 允許 / allow / go ahead”或点按钮，都视为允许一次；确认块上写明“也可以直接说：允许”。托盘不提供“始终允许”。

落地

分期与改动范围

数据层几乎不用改：AgentRun 的 step 已有 input.args / output / startedAt / finishedAt，run 已有 metadata.todos / usage / continueHint。所有新文案同步写入简体、繁体、英文三语词条。

P1 · 视觉与适配

运行卡骨架

  • 头部进度环、状态文字、n/N · 耗时、停止按钮
  • 图标取代汉字铭牌
  • 已完成步骤折叠，进行中行显示光泽文字
  • 电脑用浮动卡，手机用三档抽屉
  • 共用一个渲染器，样式改用 token

风险低：只动投影、DOM 和定位。

P2 · 信息分层

汇报与折叠

  • 叙述分为“过程”（折叠）和“对你说的话”（常显）
  • 逐步展开参数、结果和验证，按 todo 分组
  • 工具参数人性化显示并脱敏

需要把 onStatus 的语气类别与最终回复、提问区分开。

P3 · 确认链

卡内确认与失败操作

  • 卡片可见时，确认在卡内完成；不可见时退回原弹窗
  • 失败步提供“继续任务”（continueHint）和“改一下再试”

改动了确认链，要重跑冲突矩阵与确认相关专项。

P4 · 语音

三拍摘要与口头确认

  • 把 consumeTrace 的投影送到胶囊和托盘
  • maid_task 新增 confirm 动作，绑定到当前待确认的那一项
  • resolveMaidLiveControl 补“允许”的简体、繁体、英文说法
  • 确认结果只能是允许一次

依赖 P3 的确认块；需要逐个服务商验证工具回传。

还剩两个小问题

开工前再确认

  1. 手机上改成底部抽屉，可以吗？ 现在手机上的结果流跟着小球浮动，宽度占满胶囊。抽屉更方便单手操作，也不会挡住聊天内容，但交互会与电脑端不同。

  2. 含糊的回答怎么处理？ 待确认时如果你只说“好”“可以”“yes”，建议女仆追问一句“是允许绑定世界书吗？”，而不是直接执行；只有明确的“允许”类说法才直接执行。
