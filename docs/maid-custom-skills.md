# 女仆自定义技能：实现与验收

2026-09-25，基于 `da9acf3`。对应工作区《女仆自定义 Skill 完整设计》，接续首期两份内置流程。

## 功能与入口

| 入口 | 行为 |
|---|---|
| 女仆设置 → 技能 | 管理 APP 级技能库；新建、编辑、搜索、启停、复制、删除，查看占用。保留两份内置技能，可关闭或复制后编辑。 |
| 编辑技能 | 填写名称、适用说明、Markdown 正文；可预览、插入提纲，设置自动选用／仅手动及可选关联功能。保存失败保留草稿。 |
| 女仆输入框 → 技能 | 最多选择三份，显示可移除、可查看正文的标签；仅附加选择，交给任务队列接收后才消费。 |
| 技能列表 → 导入／导出 | 支持 Markdown、单文件 `SKILL.md` 和应用技能 JSON 包。先预览、补全和处理冲突，再一次提交；取消不写库。 |
| 任务卡／活动记录 | 展示实际指定或读取的技能与版本；可打开当时的正文。“已读取”不表示流程已经执行成功。 |

中简、中繁、英文文案齐全；技能正文、名称及外部元数据作为用户内容保留。列表和选择器沿用现有主题，窄屏可换行。内置复制时，启用副本可同时关闭原内置项，两个改动原子保存。

## 任务与语音

- 用户选择的完整正文进入首轮模型上下文；自动使用先提供简短目录，由模型调用 `app.search_skills`／`app.read_skill`。仅手动技能通过用户明确选择或点名使用。
- 固定系统规则与用户技能资料分开；文档不增加工具权限、不绑定另一个模型、不执行外部脚本。关联功能只在原有候选预算内提高可发现性。
- 接收任务时复制有效目录，后续读取使用这一份；运行记录仅持久化实际加载的完整版本。编辑、停用、删除不会改变已经接收的任务。
- 待确认任务、修订与显式重试恢复原技能。确认旧任务不会消费已选好的下一任务技能；显式重试不会取消或消费另一份待确认清单。
- 重试通过结构化 `sourceRunId` 定位，不依赖界面语言。附图用现有摘要去重的图片引用存储，原生记录不另塞一份 base64；本轮有新附图时优先采用，否则恢复旧图。旧文件缺失会提示重新附图。
- 实时语音继续使用原来的小球。通话暂持输入框选择，下一次 `execute` 接收后消费；聊天、查状态和确认不消费。未用完的选择在挂断后归还，任务及引用按通话隔离。已经接收的任务独立于麦克风会话继续执行。
- 自然语言的条件和执行方案继续交给模型，沿用原有短确认入口及权限链；没有增加技能关键词分流。

## 数据与限制

| 项目 | 限制 |
|---|---|
| 自定义库 | 100 份，序列化后最多 2 MiB；内置开关存于同一库 |
| 单份技能 | 名称 80 字符、文件标识 64、适用说明 1024、正文 16000，关联功能最多 12 项 |
| 单轮 | 最多明确选择 3 份；目录约 6000 字符；加载正文合计最多 24000 字符 |
| 导入 | 最多 20 个文件／合计 2 MiB；单个 Markdown 128 KiB；技能包最多 100 项 |

已知模型窗口时还按上下文及输出预留校验预算；这是请求估算，服务商的实际 tokenizer 和最终窗口限制仍有效。OpenRouter 使用已经取得的模型上下文长度，不为每次任务额外发网络请求。

原生库使用 `maid_skill_store_v1` KV；读取失败可重试，不将失败当空库覆盖。写入、导入和重新加载串行；保存成功才发布状态。内容修改递增版本，替换检查预览时的版本，外来 ID 不覆盖现有记录。同包／同批重复项默认跳过；同名不同内容默认另存，替换需明确选目标、比较内容并确认。

YAML 使用随应用打包的 `yaml` 解析器，限制大小、层级及元数据，拒绝别名、自定义标签和危险对象键。外部宿主控制字段、脚本指令、附件引用会在预览说明兼容差异，只保存说明文本，不获取或执行外部资源。新增 `build:maid-skill-deps`，发布预构建会生成浏览器依赖与许可证文件。

完整数据备份原有目录归档涵盖该 KV 与原生附件；导入完整备份后按现有流程重启读取。角色卡／单聊天分享不附带整个全局技能库，用户可单独导出技能包。运行历史只留已用版本及图片引用，不复制整个技能库。

## 模块边界

- `maid-skill-schema`、`maid-skill-store`：数据校验与原子持久化。
- `maid-skill-context`：目录快照、按需读取、分页、提示词、预算和历史版本恢复。
- `maid-skill-runtime`：输入选择、通话归属、接收前校验和选择消费。
- `maid-skill-panel`、`maid-skill-ui`、`maid-skill-transfer`：管理／选择／任务展示及文本交换。
- `app.js` 仅装配依赖、入口和生命周期；原任务队列、planner、权限及工具执行链继续负责执行。
