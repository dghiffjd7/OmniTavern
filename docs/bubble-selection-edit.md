# 气泡选区编辑

2026-09-14 已接入真实聊天。普通文字气泡中的用户消息和 AI 回复均可编辑选区，不需要启用 Agent。

## 操作

- 电脑：拖选文字，点击选区旁的「编辑所选文字」。
- 手机：直接滑动仍用于阅读；按住约 400ms 后拖动选字，松手后点击编辑入口。
- 按住不动打开原消息菜单，松手后菜单保留；菜单出现后继续拖动会收起菜单并转为选字。
- 弹窗只显示选中的文字，原文对照默认折叠。保存合并回原消息；取消、关闭、返回键不保存草稿。

## 保存与范围

原文、存储文字、用户原始输入等已有文本副本分别按可验证的对应区间替换，显示内容沿现有显示规则重新计算。未选中的原文、换行、隐藏内容和功能块保留；没有重新执行变量、记忆或生图指令。保存对象仍是原消息，不会新建段落消息。

存在回复分支时只修改当前分支，其他分支及原有元数据保留。没有本分支原文时不能借用其他分支的原文。编辑前后的会话、用户身份、存档、消息内容和分支均会校验；源文件异步读取期间发生变化也会拒绝保存。

普通聊天的小铅笔可能显示整轮原始回复。当原气泡与当前原始轮次的关系可确定时，局部修改同时合并进该轮原文，保留其他气泡和原轮次信息，不重新分发消息。打开小铅笔可看到合并后的文字。历史轮次完整原文的可用范围沿用原有小铅笔能力。

功能目前面向可准确定位的普通正文。重复文字、显示正则重写、跨复杂 HTML 结构等无法证明对应关系的选区会被拒绝，可调整选区或使用小铅笔。交互控件、推理面板、iframe、生成中消息和跨气泡选择不作为局部编辑目标。未增加全局自定义手势设置；选区宿主与编辑事务分开，后续普通工具可复用。

## 实现

- [bubble-text-selection.js](../src/scripts/ui/chat/bubble-text-selection.js)：委托事件、选区入口、触摸与菜单协调、生命周期。
- [text-fragment-editor.js](../src/scripts/ui/chat/text-fragment-editor.js)：主题弹窗、原文对照、草稿和保存状态、可见视口适配。
- [bubble-selection-edit-runtime.js](../src/scripts/ui/chat/bubble-selection-edit-runtime.js)：原文定位、文本副本替换、分支与版本检查。
- [chat-store.js](../src/scripts/storage/chat-store.js)：`updateMessageTextSelection` 校验并提交消息及关联原始轮次，沿原有 V2／原文文件持久化。

`app.js` 只增加依赖装配、显示回调和返回键接入，没有把新功能混入完整原文编辑的功能指令处理链。

## 验证

Windows PowerShell 下执行：

```powershell
npm run test:bubble-selection
```

覆盖局部替换、CRLF／隐藏块保留、其他分支不变、用户原始输入同步、陈旧提交拒绝、异步读取竞态、功能标签拒绝、关联原始轮次保存、生图文本缓存保留、将完整选区替换为空时清除旧原文文件。三语目录检查通过，简繁英各 8245 条。

实际 Windows WebView 在独立的「选区编辑体验」会话内通过真实鼠标／触摸输入验证：选择、弹窗保存、打开小铅笔核对、用户消息保存、返回取消以及 WebView 重载后历史恢复。390px 触摸模拟通过按住拖选并保存、静止长按松手后菜单保留、菜单后拖选、直接阅读滚动与手势取消。

菜单松手消失的原因已通过事件记录定位：约 696ms 菜单显示，松手后的兼容 `mousedown` 在约 841ms 触发外部关闭。宿主仅在本次按住已选字或已打开菜单时取消 touchend 的默认动作，修复后保持菜单；原长按模块未改。

需要观察真实应用时，在 Windows 启动带 CDP 的开发窗口后运行独立探针：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9222'
npm run dev
# 在另一个 PowerShell 窗口运行；会创建一个专用体验联系人和三条示例消息。
node scripts/tests/dev-bubble-selection-live-cdp.mjs
```

探针只修改自己创建的示例记录。截图和分阶段结果位于 `scripts/dev/tmp/bubble-selection-live/`；此前的隔离试验见 [可行性记录](bubble-selection-feasibility.md)。

当前 ADB 没有连接 Android 设备。WebView 触摸模拟不能代替 Android 原生选字手柄、放大镜、软键盘和真机手感验收；这些仍待真机核验。
