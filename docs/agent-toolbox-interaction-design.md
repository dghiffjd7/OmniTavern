# Agent 工具箱交互设计

状态：2026-09-17 已实现，并在 Windows dev 的真实聊天入口与隔离交互场景验证。

保留「输入框旁 + → 工具箱」入口，打开后在输入区上方显示一排彼此独立的 Agent 图标按钮。外观与输入框旁按钮共用尺寸变量：32px 按钮、18px 图标、10px 圆角，各自带边框和轻阴影；透明点击区保留 44px，外观之间自然留 12px 空隙，无共用底板。常用操作放在这一排；需要选择对象的任务展开一张小卡片；配置始终有明确的齿轮入口。AI 消息长按菜单原「Agent 工具」已移除；原有消息菜单、小铅笔与按住拖选保留。

## 已确认的问题

- 在 Windows dev 实际打开工具箱，当前聊天室只启用了格式修复。工具箱仍默认「当前草稿」，格式修复按钮因此不可用，要先改处理对象才能继续。
- `agent-toolbox.js` 只收录允许手动调用的 Agent。自动模式的输入建议即使启用，也不会出现在正常工具列表中。
- 点击任务按钮会直接尝试运行，配置按钮依赖已选 Agent／结果区出现；想先调整配置时，入口不够直接。
- 工具、目标选择、运行结果、置顶、排序和快捷键混在同一个浮层。列表还按目标是否可用排序，操作对象改变时按钮位置可能改变。
- 现有正文 Agent 入口传递 `selectedText` 后仍依赖在原文中唯一匹配；气泡选区编辑已有显示文字到原文的映射与版本校验，两条入口还没有共享完整的选区快照。

## 快捷栏的职责

1. 内建输入建议默认出现在快捷栏，关闭时也能直接开启；用户明确隐藏后继续保持隐藏。其余工具按当前聊天室／创意写作会话已启用、具备快捷操作的 Agent 生成常用列表，自动型 Agent 也可以进入。记忆等纯后台流程不默认占满这一排；是否收录取决于是否有明确的快捷动作。
2. 快捷栏名单与 Agent 开关独立。快捷按钮关闭输入建议后，该图标保留在原位，方便再打开；通过「管理快捷栏」才移出。复用现有 Agent 配置与作用域，不建立第二套业务开关。
3. 新启用的工具可自动加入；用户明确隐藏的工具不反复出现。已有置顶／顺序偏好迁移，按钮不按可用性或任务状态重新排序。
4. 使用与 AC 一致的图标。自定义 Agent 可在配置中选择图标，初始按功能类型提供默认图标。名称始终存在于无障碍标签、桌面悬停／键盘聚焦提示、操作卡和管理列表中；手机初次打开提供可关闭的简短图例。
5. 手机一行优先容纳 4–5 个 Agent；按实际可用宽度收纳，超出放进有名称的「更多」列表。固定保留齿轮入口，不靠横向滑动发现被藏起来的功能。

## 按钮点击行为

| 类型／例子 | 点击图标 | 作用范围与结果 |
| --- | --- | --- |
| 持续辅助：输入建议 | 切换当前会话开关，通过 APP 统一通知显示状态 | 图标保留；停止尚未完成的输入建议任务，旧候选不继续插入。全局默认与调用模式仍在 AC 编辑 |
| 格式修复 | 打开该轮的小卡片；已有任务／结果时直接查看 | 默认最新一轮完成回复，明确标注「整轮」，可能包含多条气泡；点击「检查格式」后运行 |
| 正文优化、输入改写 | 打开任务卡，先展示实际目标 | 明确选区优先，否则按 Agent 的已配置目标解析；从普通入口进入正文优化时默认最近一条完成的 AI 回复。支持调整为该条正文或重新选择文字 |
| 资料／建议型工具 | 打开任务卡，显示对象与一次执行入口 | 结果按说明／资料查看，不展示替换正文的操作 |

格式修复不能把某段文字当成完整结构来修复。选区可以定位所属回复，但要明确显示真实范围；不能悄悄扩大为整轮。第一版保留现有「最新可修复轮次」限制，不为工具箱重设计历史整轮修复。历史目标不可用时就地解释原因，不能默默换成最近回复。

「可修改范围」和「用于理解的上下文」分开：正文优化可以读取周围文本，但只有卡片标明的目标允许写回。没有可靠正文规则或无法映射选区时，留在卡片提示调整范围，不退回整篇修改。

任务型图标始终是进入该工具的操作／状态，不承担启停自动执行的开关。自动执行仍沿用 AC 配置；只有声明了手动能力的任务显示一次运行按钮。对于仅自动执行的任务，可查看状态和配置，不隐式改成允许手动。

## 配置入口与手势

- 快捷栏末尾固定齿轮，打开带名称的管理列表；选择某个 Agent 可直接定位 AC 中已有的配置页。关闭 AC 后再次打开工具箱，恢复管理列表与对应名称的焦点，不进入该 Agent 的任务卡、不额外准备处理目标。该入口即使没有目标、工具关闭或任务失败也可用。
- 任务卡标题旁也提供配置按钮，点击进入同一配置页，携带当前会话和目标身份。返回时保留仍有效的目标；配置改变后重新核对，失效目标要求重新选择。
- 快捷栏管理只负责显示、顺序与快捷栏快捷键；提示词、模型、上下文、目标规则等全部留在 AC，避免出现两份配置表单。
- 管理页按 APP 设置列表呈现：名称与箭头进入配置，眼睛控制快捷栏显示；已关闭的工具保留必要状态。未显示的 Agent 默认折叠。两个以上快捷工具才显示「排序」，进入后以横排上下箭头代替眼睛，完成后收起；长列表滚动时标题与完成入口固定。显示／排序操作保留键盘焦点，Esc 可先结束排序或快捷键录入。
- 快捷键的作用明确标为「打开工具箱」，只在 APP 内生效；需 Ctrl／Alt／⌘ 配合另一个键，避免占用日常单键输入。录入时显示示例，单键即时提示且保留原绑定；Esc／取消退出录入，清除按钮解除绑定。录入截获按键，按住后的重复事件不反复打开工具箱。配置返回记录仅使用一次，明确选择新消息或切换会话时丢弃旧记录。
- 任务卡保留真实范围、数量、对象选择、内容摘要与执行按钮；刷新使用图标，完整内容可展开。从选区进入整轮格式检查时才额外解释范围。图标保持无障碍名称，去掉默认常驻的操作说明与重复状态文字。
- 第一版不给快捷栏按钮添加长按／双击动作。Agent 如需按住录音、拖动等操作，在它展开后的操作区执行；气泡区域继续沿用长按菜单与按住拖选，输入框继续沿用建议接受手势。
- 不让「长按」成为发现名称或进入设置的唯一方式。任务卡是选择目标与执行的工作区，执行后不再追加无意义的确认弹窗；修改结果进入现有红绿差异审阅并由用户应用。

## 选区入口

- 先选文字：保留现有小铅笔手动编辑；在选区入口旁提供工具箱入口，将该选区带入同一套 Agent 工具。用户不必先回输入区再重选文字。
- 先选工具：正文优化卡内点击「选择文字」，卡片暂收起，显示轻提示与取消入口；沿用现有选字手势，完成后回到任务卡并显示选区摘要。
- 在点击工具入口导致焦点转移之前捕获选区。快照携带会话／角色作用域／存档／消息 ID／当前回复分支／原文版本与可验证范围，不能只依赖随后读取的浏览器 Selection 或文字搜索。
- 第一版保持单条消息内的可映射正文。跨气泡、iframe、生成中消息、隐藏思考及功能块继续遵守现有边界；重复／重写内容不能唯一映射时，不猜测位置。
- 原文或分支变化时立即标记旧结果过期；应用前再次校验。沿用现有差异审阅、当前分支写回与原文保护，不创建第二套提交逻辑。

## 状态、布局和性能

- 常态图标清晰；开关状态使用形状／标记与提示共同表达，不能只靠颜色。运行中显示局部进度，待审阅用角标；点击运行中的任务打开进度卡，取消放在卡片内，避免重复请求。
- 没有有效目标时仍可打开卡片了解原因、选择范围和进入配置；只有执行按钮不可用。空快捷栏保留一个明确的「添加工具」入口。
- 图标触控区至少 44px；沿用 APP 的表面、边框、强调色和阴影。弹层相对可见视口定位，避开软键盘、安全区和输入框，展开卡片不推动聊天列表。
- 悬停／键盘提示按快捷栏容器与可见视口共同限制位置，长名称可换行；鼠标提示优先于另一按钮的键盘焦点提示。仅在进入按钮、布局或当前提示内容变化时定位，不跟随每次鼠标移动测量。
- 保留稳定 DOM 和按钮位置。进入设置、打开任务卡、收起和返回分层处理；Esc／返回键逐层退出，焦点回到仍可见的触发点。不抢占输入建议的 Tab／方向键，工具栏内的键盘导航仅在工具栏取得焦点时生效。
- 若采用浮现动效，使用短时 opacity／transform，尊重减少动态效果；关闭后停止局部进度动画，不加周期性全局刷新或大面积模糊。
- 配置／会话变化时才更新工具目录，任务变化只更新对应图标和卡片；选区拖动不触发 Agent 请求，不每帧重新组装 Prompt，不用整块 innerHTML 重建正在操作的内容。

## 实现与验证

1. `agent-toolbox-model.js` 管理按会话保存的快捷栏成员、显式隐藏、稳定顺序和旧偏好迁移；开关复用现有配置保存与继承。`agent-icons.js` 共用 AC／工具箱图标，自定义图标进入原配置草稿与保存流程。
2. `agent-toolbox.js` 管理图标栏、任务卡、结果入口和选择流程；`agent-toolbox-view.js` 负责主题样式与固定 DOM。任务结果有独立的「任务与结果」入口，自动输入建议的结果无需点击开关来查看。
3. `agent-tool-targets.js` 只读准备实际处理目标，保存上下文、存档、消息、分支、原文与可验证范围；从显示文字提取选区沿用现有映射，执行与写回沿用 Agent 原差异审阅和提交保护。原文、配置或整轮来源变化时拒绝旧目标。
4. `bubble-text-selection.js` 在现有小铅笔旁增加工具箱按钮，并接入「先选工具→选择文字→返回同一任务卡」。`app.js` 仅新增来源回调、选区装配和返回键入口，移除旧菜单 action；新逻辑已有独立边界，无需为少量装配另做拆分。

`agent-invocation.js` 继续作为运行权限来源。仅自动执行的任务可以查看状态／配置，不通过工具箱绕过调用模式。格式修复使用既有最新整轮来源解析；选区不让其变成局部格式修复。正文工具的「使用配置范围」恢复该 Agent 已配置的处理范围，卡片显示其真实标签（正文、指定部分或完整回复）。

Windows PowerShell 专项覆盖偏好迁移、当前会话开关与全局继承、可验证选区、实体／CRLF／隐藏内容保护、差异审阅、分支／存档／配置／整轮过期、调用模式与取消、AC 图标和菜单。原生 WebView 隔离验证桌面及 390／320px、真实鼠标拖选、手机长按菜单／按住拖选／普通滚动、选区工具触控、结果入口、快捷键与稳定 DOM；使用内存配置与本地任务 fixture，没有请求远程模型或修改真实聊天内容。

## 生图入口整合评估（待实施）

建议把手动 AI 绘图收进工具箱。「+」保留上传图片、附件、工具箱三个入口；工具箱按现有独立按钮样式放置输入建议、格式修复、AI 绘图和其他已启用工具。手动生图多点一次，输入区减少一个按钮及其间距（当前约 38px），也能沿用工具箱的排序与更多收纳。

AI 绘图以普通工具身份接入，点击打开现有生图弹窗，确认后才请求生成；继续使用当前聊天／创意写作的图片用途、参考图、参数、相册／素材与任务流程。工具箱的齿轮负责显示与顺序，各工具的配置入口跳转到原有所属页面，AC 继续管理 Agent。

当前快捷栏目录来自 `listAgentConfigurations`，执行分支按 Agent 类型分发，因此实施时需要为普通工具增加独立入口描述与点击回调。可以由 `agent-tools-app-runtime` 接入已有 `openChatImageGenerationFlow`，保持现有参数和 `useComposerFallback: false` 行为，复用原弹窗、生成任务与持久化；主要改动集中在快捷栏数据源／管理列表和 `app.js` 的入口装配。应让「工具箱」作为通用名称覆盖普通工具与 Agent，避免用户把所有按钮都理解为后台 Agent 开关。

这一轮只完成输入建议默认入口和悬停边界修正；生图入口保持原位，迁移尚未实施。
