# 气泡拖选与局部编辑可行性验证

> 2026-09-14 更新：已接入真实聊天及持久化，见 [气泡选区编辑](bubble-selection-edit.md)。下面保留 2026-09-13 的隔离试验记录，其中“尚未接入”的描述为当时状态。

2026-09-13。范围是普通文字气泡的交互试验，尚未接入正式聊天或自定义工具注册。

## 结论

电脑鼠标拖选可以沿用原生文字选择。手机可以试行「直接滑动阅读、按住后拖动选字、按住不动打开消息菜单」；Windows WebView2 的触摸模拟已走通该规则，但 Android 原生选字手柄、菜单和软键盘尚未验收。

选区识别适合成为 APP 的共用能力，后续把「编辑所选文字」作为普通工具接入。这里没有新增 Agent、模型请求或正式消息写入，也没有决定将编辑功能固定为内建动作。

## 实际观察

试验使用 `appBridge.getChatUI().buildMessageElement()` 建立独立测试气泡，沿用真实长按菜单、原文映射和局部替换函数。编辑结果只在试验内存中保存，可撤销。试验页拦截原菜单和气泡按钮的聊天操作，避免手动查看时调用真实会话动作。

| 操作 | 当前实现 | 触摸试验增加协调后 |
| --- | --- | --- |
| 电脑按下拖选，再停住超过菜单等待时间 | 有选区，不弹菜单；可编辑局部原文 | 沿用原生选择 |
| 手机模拟中按住不动 | 显示真实消息菜单 | 保留同一菜单 |
| 手机模拟中按住约 460 ms 后跨行拖动 | 浏览器接管手势，没有文字选区 | 正确选字；无菜单、无滚动 |
| 菜单已出现后继续拖动 | 菜单保留，没有文字选区 | 收起菜单，转为选字 |
| 手指落下后立即纵向滑动 | 正常滚动，不弹菜单 | 正常滚动，无选区与编辑入口 |
| 反向拖选与手势取消 | 未在基线重复验证 | 反向选择正确；取消清空预览，不编辑 |

触摸试验还通过真实触摸点击选区旁的「编辑所选文字」、输入替换内容及点击保存。保存后的完整原文严格等于只替换选中片段的预期结果，其他文字、CRLF、隐藏思考块和表格指令保持原样；撤销恢复完整原文。

## 编辑弹窗与保存范围

2026-09-13 15:54 CST 更新：隔离试验中的弹窗已按现有主题和图标体系美化。桌面居中，手机靠近可见视口底部；输入区采用柔和边框，原文对照默认折叠，显示字数与「仅替换所选文字」。未修改时禁用保存，取消或关闭只丢弃本次草稿。原生 dialog 负责模态焦点与 Esc，较矮视口下正文可以滚动，保存按钮留在底部。

「局部小铅笔」的目标语义是：只替换选区，再把结果合并保存到原来那条消息。保存对象仍是完整消息，未选中的原文不变；再次打开完整小铅笔应能看到合并后的内容，无须再保存一次，也不单独生成段落消息。存在回复分支时只更新当时选中的当前分支，并在提交前检查消息、分支和原文版本。以上是真实消息接入时的约束；本原型仍只写试验内存。

源码核对发现，现有小铅笔通过 `chat-ui.js` 的 `edit-assistant-raw` 进入 `app.js` 完整原文编辑链；聊天模式还可能编辑整个来源轮次并重新分配气泡，功能标签改动也可能触发相应处理。因此，正式的局部工具应复用现有文本编辑的原文定位、提交校验与当前分支持久化能力，限定可修改范围，保留功能标签和既有执行状态。可以参考现有 Agent 文本编辑提交路径，但无需运行 Agent；本轮没有修改该生产链。

本轮在 Windows PowerShell 启动的实际 WebView 内做一次弹窗专项检查：桌面、390 × 780、320 × 420、390 × 380 视口下按钮可见且触控高度至少 44px；展开原文对照、字数/保存状态、精确替换、撤销与关闭草稿均通过。内建深色主题的纯 token 只施加到试验容器，没有更改用户主题设置；截图复核后将主按钮文字改用主题反色 token，并单独复核该处显示。较矮视口仅用于布局验证，不代表 Android 软键盘验收。未重复执行此前的完整手势试验。

## 为什么不能直接照搬输入建议条

输入建议条从开头选取一个前缀，并在独立按钮区域使用 `touch-action: none` 接管触摸。正文需要任意起点、跨行与反向选择，还需要保留阅读滚动。

当前气泡的 `touch-action: manipulation` 允许浏览器接管滑动。只加按住计时器和高亮逻辑，无法保证后续仍收到拖选事件。手势开始后再修改 `touch-action` 不会影响当前手势，见 [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。

试验保持原有 CSS，在初始滑动时放行滚动，在按住后开始拖动且触摸事件仍可取消时阻止该次滑动，并根据真实文字位置建立选区。同时清除菜单计时；已有菜单则收起。它没有在整块正文上永久禁止滚动。

## 原型边界

- 选区旁提供明确的编辑按钮；松手不自动打开编辑框，以便保留复制和调整选区。最终入口仍可调整。
- 保留原菜单意味着较晚才开始拖动时，菜单可能已经出现；试验验证的是继续拖动可切换为选字，不能声称所有时序都从未显示菜单。
- 覆盖普通文字、跨行选择、反向选择、取消和单次局部编辑。没有覆盖复杂 Markdown/HTML、iframe、跨气泡选择、边缘自动滚动、二指手势与全部系统菜单行为。
- 现有原文映射仍会拒绝重复或无法唯一定位的显示文字，不能用整条显示文本重建原消息。
- 无连接的 Android 设备；触摸模拟不能代替 Android 原生选择、软键盘、放大镜和长按手感验收。
- 试验仅冻结测试原文并校验，未接入真实消息/分支/存档的提交事务；正式工具化时需沿用这些目标校验和撤销机制。

## 复现与产物

在 Windows PowerShell 中启动可检查的开发窗口：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9222'
npm run dev
```

原行为观察与新交互试验分别运行，各自使用隔离气泡：

```powershell
node scripts/tests/dev-bubble-selection-feasibility-cdp.mjs
node scripts/tests/dev-bubble-selection-feasibility-cdp.mjs --touch-trial --keep
```

`--keep` 保留试验页供操作，点击「关闭验证」恢复原 APP；脚本恢复进入前的视口。普通测试不自动运行这份探索脚本。

只打开试验页、无需重复运行检查时：

```powershell
node scripts/tests/dev-bubble-selection-feasibility-cdp.mjs --touch-trial --show
```

结果和已查看截图保存在 `scripts/dev/tmp/bubble-selection-feasibility/`：`observations.json` 为原行为，`touch-trial.json` 为新交互；`trial-touch-selected.png` 与 `trial-touch-editor.png` 展示手机宽度下的选择和编辑。
