# 女仆执行卡与语音任务状态设计评估

更新时间：2026-09-23 CST（v2 已实施）
状态：P1–P4 已实施并在 Windows 原数据 dev 验收；手机抽屉、只认“允许 / yes”两项按用户确认执行。与设计的差异见文末“实施记录”。

原型：`docs/prototypes/maid-run-card/index.html`（单文件，可直接打开；含状态切换、电脑／手机切换、手机抽屉三档、逐步展开、内联确认、全过程播放、语音三拍摘要）。

## 已确定（2026-09-23 用户反馈）

1. **语音任务只显示摘要。** 流程是下达任务 → 女仆执行 → 用语音汇报结果；屏幕只保留一句话，要看步骤时再点开。
2. **去掉 计/行/成/败 汉字。** 改为用图标形状、颜色和头部状态文字三重表达状态。
3. **过程折叠，汇报必显示。** 思考与工具步骤默认折叠；女仆对用户说的话（最终汇报、中途提问、需要处理的提示）总是显示。
4. **语音说“允许”算确认，视为允许一次。** 简体、繁体、英文同步支持；语音永远不能触发“始终允许”。
5. **结果流按设备分别设计。** 电脑与手机各自适配，不共用同一种容器。

## 现状（代码核对）

- **渲染器有两个，共用纯投影** `projectMaidRunToTraceView`（`src/scripts/ui/chat/execution-flow-runtime-utils.js`）：
  - 输入胶囊结果流（`maid-command-input-runtime-utils.js`），为主画布；
  - 执行流面板，为兜底。
- **卡片形态**：PLAN → 每个工具一张 TOOL·NN → DONE，每张分量相同；状态用汉字加 6px 圆点表达；结果流最高 `min(42vh, 188px)`。
- **有数据但未显示**：`step.input.args`、`step.output`、起止时间、`toolCalls`、`usage`、`metadata.todos`、`continueHint`、读回验证。
- **确认**：确认走 `requestMaidToolConfirmation` 弹出的 appChoice 模态框，流里只显示“等待授权”。
- **语音**：
  - 任务默认 `showInput:false`，`maidVoiceRuntime.consumeTrace` 吞掉投影，小球旁只有一行徽标。
  - 通话中没有口头确认的通道：`maid_task` 只有 `execute / status / cancel / revise` 四个动作；GPT-Live 的正则兜底 `resolveMaidLiveControl` 已覆盖简体、繁体、英文的停止、状态查询和修正，但没有覆盖“允许”。

## 运行卡（文字任务）

- **一次任务 = 一个对象。**
  - 头部：进度环（已完成步数／总步数，环心为当前步序号）、目标、`状态 · n/N · 耗时`、常驻停止按钮。
  - 终态时进度环换成对勾或叉（弹入 300ms），停止按钮换成收起按钮。
- **状态三重编码**：

  | 状态 | 图标 | 颜色 |
  | --- | --- | --- |
  | 排队 | 空心圆 | 灰 |
  | 执行中 | 旋转弧，标题加粗 | 蓝 |
  | 等待确认 | 时钟 | 琥珀 |
  | 完成 | 细勾 | 灰 |
  | 失败 | 叉 | 红 |
  | 跳过 | 短横 | 灰 |

  绿色只用于整次任务成功时头部的对勾。
- **步骤行**：
  - 构成：动词标题 + 等宽目标 chip + 耗时。
  - 展开后显示参数、结果和读回验证。
  - 超过 2 步的已完成部分收成“已完成 N 步”。
- **叙述分两类**：
  - 过程叙述（onStatus 的思考／进度）：执行中显示为光泽进行行，其余收进“思路”，默认折叠。
  - 对用户说的话：以带“侍”标记的汇报气泡显示在卡外，始终可见。包括：
    - 最终回复；
    - 中途提问，例如失败后问“要先创建角色卡吗？”；
    - 需要用户处理的提示。
- **卡内确认块**：
  - 内容：标题、影响对象、风险标签。
  - 按钮：取消 / 始终允许 / 允许一次。
  - 卡片不可见时，退回原弹窗。
- **三级视觉层级**，同时只有一个第一层：
  - 第一层：当前步、待确认、失败、汇报；
  - 第二层：目标、进度、耗时；
  - 第三层：已完成步骤、参数、思路。

## 设备适配

以 `宽度 ≤ 760px && (pointer: coarse)` 判定使用手机方案；宽屏触控设备（平板）沿用电脑布局，但放大点击区。

| 方面 | 电脑：锚定小球的浮动卡 | 手机：底部抽屉 |
| --- | --- | --- |
| 位置 | 跟随小球，沿用现有的上下翻转；可停靠为侧边执行流面板 | 从底部升起，输入胶囊固定在抽屉底部，跟随键盘上移（`visualViewport` + 安全区） |
| 高度 | 上限 `min(60vh, 480px)`，卡内滚动；完成后收成头部 + 汇报 | 预览约 150px（头部 + 当前一行）／半屏／全屏；执行中默认预览，等待确认或失败时升到半屏，展开详情时拉到全屏 |
| 展开 | 悬停时出现箭头；键盘 ↑↓ 移动、Enter 展开 | 箭头常显，每行点击区至少 44px |
| 确认 | 卡内原位显示；Enter 允许一次、Esc 取消；危险操作的默认焦点在取消 | 固定在抽屉底部、输入胶囊之上，按钮加大 |
| 自动滚动 | 离底部 28px 以内才跟随 | 预览档不滚动；半屏以上同电脑 |
| 关闭 | 点外部或按 Esc；任务继续在后台执行，小球外圈显示状态 | 下滑或点遮罩；不中止任务 |

## 语音任务（Realtime）

- **小球外圈只分状态，不显示步骤进度**：

  | 阶段 | 外圈 |
  | --- | --- |
  | 接收、执行 | 蓝色慢转 |
  | 等待确认 | 琥珀色呼吸 |
  | 已汇报 | 绿色停留 1.2s |
  | 失败 | 红色，保留到用户查看为止 |

- **胶囊只放一句话**，就是女仆此刻会说的那句，例如“好的，这就去建三个私聊”“要绑定世界书，允许吗？”“已汇报：3 个私聊都建好了”。
- **托盘里每个任务三行**：
  1. 用户的指令摘要；
  2. 接收 → 执行 → 汇报三拍进度；
  3. 一句结果或当前在做的事，以及“查看详情”。

  点“查看详情”才打开完整运行卡；托盘不显示步骤列表。托盘还包含：麦克风开关、单个任务的停止按钮、最后一句字幕、暂停播报、记录与输入，以及红字的“结束语音”。
- **口头确认**：
  - 需要确认时，托盘自动展开，女仆口头询问。
  - 确认块写明“也可以直接说：允许”，只提供“取消 / 允许一次”两个按钮。
  - 实现要点：
    - `maid_task` 新增 `confirm` 动作，绑定当前待确认项的 ID，且只能产生“允许一次”；待确认项变化或超时后，旧的确认失效。
    - `resolveMaidLiveControl` 补充“允许 / 允許 / allow / approve / go ahead”等说法。
    - 新增的界面文案同步写入三语词条。

## 实施记录（2026-09-23）

- **模块**：
  - `maid-run-card-model.js`：纯视图模型。
  - `maid-run-card-dom.js`：共享渲染器，按行 id 原位更新，样式只用 token。
  - `maid-tool-confirmation-runtime.js`：确认逻辑从 `app.js` 整块迁出，新增卡内确认、承载面关闭时退回弹窗、语音允许一次。
  - `app.js`：只保留装配。
  - 工具注册表在确认请求里附带 `runId`。
- **输入胶囊**：
  - 结果流改为“运行卡 + 汇报气泡”。
  - 执行中的叙述并入卡内“思路”；没有 run 的回复在结束后收成一行折叠。
  - 桌面结果流上限改为 `min(60vh, 480px)`。
  - 手机按 `(max-width: 760px) and (pointer: coarse)` 切为三档抽屉（把手点击或拖动换档，下拉到底收起）。
  - 提交中只淡化输入框，不再让整张卡片半透明。
  - 发送、停止、圈选等按钮的硬编码蓝／红改为主题 token。
- **执行流面板**：承载同一张运行卡。头部只留标识、收起和关闭，停止按钮移入卡内；有待确认项时自动展开。
- **语音**：
  - `maid_task` 新增 `confirm`，GPT-Live 兜底补“允许 / 允許 / yes / allow”。
  - 没有待确认项时，“yes / 允许”按普通回答交给女仆处理。
  - 需要确认时，托盘自动展开，并通过任务更新让语音模型口头询问，每条只问一次。
  - 小球外圈显示状态，胶囊显示一句话，托盘显示三拍摘要、单个任务停止、最后一句字幕。
- **与设计的差异**：
  - 按 todo 分组、失败卡内的“继续任务 / 改一下再试”按钮尚未实现。女仆的后续提问仍以汇报气泡和原有操作按钮呈现。
  - 确认块只提供按钮，没有做 Enter／Esc 快捷键，避免与输入框的回车发送冲突。
  - 手机全屏档不加遮罩。
- **已知遗留**：女仆头像贴图的层级高于小球托盘，会遮住托盘右上角，这是原有问题，本次未处理。
